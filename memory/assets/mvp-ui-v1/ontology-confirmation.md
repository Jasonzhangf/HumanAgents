# HumanAgent MVP V1 语义确认单

全部条款已逐条批准。07、08、19、20 采用 revision 2，其余采用 revision 1。[WebUI V1 定稿](聊天界面审阅.html)

### [01　项目工作区与默认目录](../../L2/mvp-v1-01-project.md) · r1 已批准

一个工作区可包含多个项目；新建或编辑项目时指定工作区、项目根目录。项目显式 Agent 从该项目根目录开始工作。

### [02　唯一显式入口与身份](../../L2/mvp-v1-02-identity.md) · r1 已批准

无项目时唯一直接暴露的显式 Agent 是 Alex（CEO）；每个项目恰有一位 Jenny，同时是该项目唯一 manager 和显式 Agent。

### [03　成员配置与寻址](../../L2/mvp-v1-03-member.md) · r1 已批准

成员以「项目名.成员名」通信和绑定任务。可配置成员角色提示词、provider、model。architect、patrol、reviewer、tester、executor 按需添加，用不同颜色显示；支持不同成员同时展开会话。

### [04　自动分派的默认决定](../../L2/mvp-v1-04-dispatch.md) · r1 已批准

建议对自动分派先匹配本项目已配置的对应职责，无匹配者交回本项目 Jenny 接收协调；保留手动指定地址。多个同职责成员的排序暂留实现阶段。

### [05　任务归属与任务板](../../L2/mvp-v1-05-board.md) · r1 已批准

CEO 通用任务归无项目的 Alex。项目任务归 Project × 具名角色的 Board。支持增删改查、当前及完成历史；改派后归接手者的板。巡检是任务类型。

### [06　项目树与通用会话](../../L2/mvp-v1-06-session.md) · r1 已批准

一级项目目录支持 CRUD，下挂成员、项目记忆 Agent、Buglist。成员及记忆 Agent 打开共享会话控件；顶部 Board、定时任务打开右侧抽屉，可按当前身份编辑。能力与 UI 解耦。

### [07　主 Topic 与旁支的并行会话](../../L2/mvp-v1-07-topic.md) · r2 已批准

显式 Agent 默认打开主 Topic。每个 side topic 有特定主题和独立 session。主 Topic 与旁支可同时执行，用户可随时切换和切回，切换不暂停另一会话。消息、草稿和待答问题归原 Topic；创建或打开旁支不改变默认话题或默认项目。

### [08　任务关系与记忆 Agent](../../L2/mvp-v1-08-runtime.md) · r2 已批准

任务图从显式 runtime 关联隐式编排 runtime，各业务 Agent 关联自己的记忆 runtime。每个实例有独立 ID，可查看状态和会话，项目保留记忆入口。记忆 Agent 定期运行，也接受主动触发。它检查已记录的 session、文档和代码，提取和优化 skills 与项目记忆，按项目或全局作用域提交候选。用户审计通过后才写入对应库。

### [09　工作区 Buglist](../../L2/mvp-v1-09-buglist.md) · r1 已批准

同一工作区的项目入口指向同一份 Vikunja Buglist；项目成员 Board 管理各自任务。

### [10　多轮提取、投递及原任务续跑](../../L2/mvp-v1-10-relay.md) · r1 已批准

显式 Agent 对简单问题直接作答，多轮复杂需求提取目标、约束和交付物；一次提交完成新任务确认与投递。隐式负责执行。执行中转问、回答、继续和可核对结果在原对话完成。变更既有目标或范围按既有确认规则。

### [11　持久区、动态区与工具语义](../../L2/mvp-v1-11-turn.md) · r1 已批准

聊天用一条线分隔历史与当前。历史保留每轮用户原文及摘要，点击打开细节。用户靠右、Agent 靠左。动态区展示当前轮次全部可见文字，工具由独立模块按调用和对应结果语义显示。消息顶部小行容纳图标、阶段、耗时和动画。

### [12　Ask 选择、自定义与引用](../../L2/mvp-v1-12-ask.md) · r1 已批准

问题下列出模型给出的可选项，最后一项允许手填自定义答案。就地提交的两种答复均引用具体原问题，下方显示答案。底部输入框发送独立消息。

### [13　全程可观测与模型响应](../../L2/mvp-v1-13-observe.md) · r1 已批准

发送、需求整理、排队、等待模型、流式接收、工具执行、等用户、结果核对、终态均按实际事件显示。模型响应独立小行；等待琥珀、接收蓝、完成绿、失败红，配文字和图标。各步独立计时；并行步骤各自计时，刷新、切 Topic 或收到片段保留起点。

### [14　错误呈现与恢复](../../L2/mvp-v1-14-retry.md) · r1 已批准

暂态错误记录错误码、原因、已等时长、重试序号与倒计时；按既有最多十次退避规则续跑，耗尽显示失败。可能已生效的操作先核对结果。订阅断开单独恢复。

### [15　V1 交付边界](../../L2/mvp-v1-15-boundary.md) · r1 已批准

第一阶段交付 WebUI 及其真实用户闭环。Debug 按选中 runtime 预留角色提示词、当前 context layout 与堆栈位置；真实采集与调试后置。

### [16　按模板新增成员](../../L2/mvp-v1-16-template.md) · r1 已批准

在项目成员区选模板、新增具名成员。模板分别提供系统提示词（共同工作约束）与角色提示词（岗位职责）；创建时复制为该成员的配置，可独立编辑两层及 provider、model。编辑成员只影响本人，重名时保留原成员并提示。

### [17　项目地址与人员地址](../../L2/mvp-v1-17-address.md) · r1 已批准

V1 在本机工作区内解析逻辑地址。仅指定项目名时，由该项目 Jenny 接收；指定「项目名.成员名」时只投该成员。界面可在当前项目内选择成员并补全地址。Alex 为独立 CEO 地址。缺失或歧义显式报错，禁止广播或改投同名成员。

### [18　消息投递与回执](../../L2/mvp-v1-18-delivery.md) · r1 已批准

每封消息有稳定消息 ID、来源和目标逻辑地址、消息类型、正文；按需关联 Task、Topic、原消息或原问题。发送后可区分待投递、收件方已接收、接收方已处理及失败。已接收以进入收件队列为准，已处理以接收方处理回执为准；任务完成另由 Task owner 裁决。暂态失败按既有退避策略用同一消息 ID 重投；重复送达只入队一次、只触发一次。永久寻址错误直接反馈。

### [19　消息投递的三个执行时机](../../L2/mvp-v1-19-trigger.md) · r2 已批准

投递给 Agent 的消息按发送方选择使用 steering 或 queue。立即执行时，走标准停止操作取消当前正在执行的任务，完成收拢后执行新消息。下一轮插入时，当前轮结束后在下一轮开始时处理。执行结束后插入时，等待 Agent 当前执行结束后处理。队列接收与实际执行分别记录；原消息的 Task、Topic 与问题引用随投递保留。

### [20　跨机器寻址与项目展开](../../L2/mvp-v1-20-remote.md) · r2 已批准

跨机器成员地址使用 machine.project.name，跨机器项目地址使用 machine.project。项目树按机器展开项目，再按项目展开成员；通过项目地址交该项目 Jenny，完整成员地址只投指定成员。V1 保留同机投递并表达远端地址与层级，真实跨机器投递沿用消息 ID、引用、回执和去重语义，待后续接通验证。
