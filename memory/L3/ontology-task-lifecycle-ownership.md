# Ontology: Task owns task state; execution records own their own outcomes

User-approved HumanAgent ontology rule v1 (2026-11-21). Task-scoped execution lifecycle ownership is divided by object responsibility.

Task owns only the four main states created, active, waiting, and closed, plus the closed outcome. A task-scoped Cycle records one finite execution round under its bound Goal revision and its own execution result. A task-scoped Operation records its own auditable, cancellable, or settlable effect status and result. A task-scoped Checkpoint records durable recovery facts, evidence, and recovery state; it is not Task closure or proof that an external effect succeeded. A shared projection label does not make these objects share one lifecycle truth.

After an execution ends, the Cycle, affected Operations, and Checkpoint each record their own results. The Task owner evaluates the currently confirmed Goal and the available results, decides the whole Task state, and commits that decision to the Organ Journal. The Task status shown by the interface follows that committed decision. A subordinate success must not be copied directly into Task state. When confirmed appended work remains, a successful prior Cycle does not make the Task succeeded; the Task remains active or waiting until its current Goal is assessed again.

A taskless interaction uses InteractionClosure and carries no Task, Cycle, Operation, or Checkpoint identity. The task owner is packages/core. packages/runtime owns Cycle coordination, Operation settlement coordination, and Checkpoint submission. packages/adapters/jsonl owns durable Journal append.

This rule records approved semantics only. The proposed identity/transition gate at the Task public-state commit is not yet bound or executed, and no implementation claim is made.
