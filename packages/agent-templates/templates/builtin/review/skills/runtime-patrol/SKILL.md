## 触发与权限

仅在 Runtime 明确提供项目巡检职责，以及现有订阅的到期事件或授权巡检请求时执行。检查请求须有项目、巡检来源与被检查范围。普通 review、任务执行邀请、会话文本和无法验证的事件不触发巡检。巡检只使用当前已授权的只读状态、会话和 Board 端口。使用现有巡检报告入口提交回执。

## 一次巡检

1. 读本巡检目标、行动项和评估标准，再读项目已批准的目标、行动项、评估标准、登记依赖和上次回执。核对版本、负责人和范围。逐项目标检查每项评估标准都有对应行动项，且行动项有明确动作和可查证产物。巡检本身也须有清晰行动项与标准，如「核对 Jenny 的当前活动」，评估标准为「按授权项目、Jenny 身份和当前 runtime 代次定位 session，并引用实际活动与 Board 记录」。缺目标、行动项、标准或授权来源时，在对应检查项记为 `unknown` 并列出缺口、应补负责人及恢复条件。继续检查有依据的其他项。
2. 读取授权的项目 runtime 清单和当前可观测状态。核对当前成员名字、runtime ID、代次、采样时间、实际活动与任务绑定。区分 idle、busy、offline 和未知。检查可承接容量、仍待派的 ready 项、失联和无归属资源。Board 只能说明任务责任和状态，不能单独证明 runtime 闲忙。
3. 读取同项目 Jenny 的当前授权 session。对照稳定身份、有效 session 绑定和当前代次。只取判断所需的任务、动作、回执和时间。旧代次只用作历史；授权受限、无法匹配或存在多个候选时标记未知。
4. 按「目标 → 行动项 → 评估标准 → 实际证据」逐项判断，并和上次回执比较。对照 Board 检查 Jenny 的动作是否推进该行动项、解除有效依赖、遗漏有可用容量的高优先级任务，或重复唤醒却没有新进展。缺评估标准时只报告缺口。已登记的合规等待、按授权并行推进其他任务及非必要例行汇报缺失，均不足以判为偏离。
5. 返回本轮回执。关联现有项目记录、事件或巡检 occurrence、目标版本。每个检查项写明目标与行动项引用、评估标准、实际观测和证据时间、与上次的差异、结论、责任人、下一步及可复核条件。将偏离、runtime 异常及缺少目标或标准等可处理缺口交给负责人。只在真实回执可见时记录已送达。重复事件复用现有回执；同一问题只在证据或影响变化时更新。

## 回执结论

- `aligned`：有效证据支持当前行动项与目标一致。按标准记录实际进展。行动项完成仍须有满足评估标准的证据，登记的合规等待须附依赖和恢复信号。
- `deviation`：有直接证据表明已执行动作与目标、优先级或范围冲突。附目标、行动项、评估标准、实际动作和影响。
- `runtime-anomaly`：已确认有效代次存在异常。附影响任务、观察时间和实际 owner。
- `unknown`：来源缺失、失败、过期、歧义或关联无法验证。保留已核实部分、缺失事实及下次可核对的信号。
- `rejected`：巡检请求无权、scope 不匹配或来源无效。保留拒绝回执。

一次回执可同时含 runtime 异常和 Jenny 偏离等不同检查结果。所有结论由同一报告入口返回。恢复、重试和新唤醒作为下一次事件处理。巡检员不改任务、资源、订阅或会话。
