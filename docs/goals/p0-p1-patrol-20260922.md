## 1. 巡检范围与优先级判定

本目标是调度与收口的唯一计划，不新建缺陷库、scheduler 或 task truth。缺陷真源是 `appsdk bug`；优先级按下述规则在当前 mainline 上重新判定，不沿用旧标签臆断。

- **P0**：阻断显式大脑推理或 UI 主链路可用，或造成数据丢失、越权、假成功。
- **P1**：显式标记 P1，或阻断真实前端跑通（理解 → 确认 → 派发 → 执行 → 观测）的实质环节。
- **P2**：不阻断主线、可后置的收紧、死代码与设计确认项。

## 3. 完成定义

全部满足才算本轮完成：

1. 每个 P0/P1 缺陷要么有合入 main 的修复 + 独立 review PASS + 同入口证据，要么明确记录阻塞原因、owner、解除条件与恢复触发。
2. 每个候选在独立 clean worktree 完成，命中授权范围和唯一 owner；共享组装点由单一集成 owner 接线。
3. main 保持可验证：`pnpm typecheck`、受影响 focused tests、受影响 app/runtime 测试通过。
4. 每个修复合入后从 main 重建产物、重启本地实例、同入口复验真实行为。
5. 已合入任务的 worktree 与本地分支回收；playground 只剩活跃任务；无孤儿进程、无泄漏端口。
6. 记录 candidate/main SHA、review verdict、产物版本/哈希、运行身份与资源回收证据；缺项只能报 `INCOMPLETE`/`UNVERIFIED`。

## 4. 调度边界

- 实现者与独立审查者必须是不同 agent；每个 worker 独占新 worktree 与不重叠文件范围。
- 共享组装点（`packages/app/src/cli.ts`、`ui-runtime/service.ts`、`server.ts`、`docs/ui/runtime-api.js`）由单一集成 owner 持有。实现者先交独立模块和测试，再由该 owner 接线；不得平分目标造成重叠写入。
- 禁止在 dirty main 上改业务代码；禁止修改 `.appsdk/**`；禁止删除他人 worktree、分支、进程或证据。
- 标准本地交付（candidate → review PASS → merge 到 clean main → 重建 → 重启 → 同入口复验 → push）按项目授权执行；删除、回滚、迁移、发布、生产变更仍需单独授权。
