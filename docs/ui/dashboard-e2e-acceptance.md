# Dashboard 真实入口验收与资源收口

本文件约束 Dashboard 输入、任务执行、语义观测与结果展示的验收。验收范围由本轮有效需求、改动和已接受计划决定。页面可打开、Provider 显示 connected、编译通过或单次 API 成功，都不能代替对应用户行为的真实证据。

## 最小充分范围

- 每项用例说明对应需求或关键不变量、具体失败模式，以及系统出错时必须失败的断言。
- 新增用例前考虑失败可能性的依据、失败影响、执行和维护成本。概率允许未知，不编数字。抓错能力用已有红测或可执行反例证明；尚未执行则标 UNVERIFIED。
- 复用仍有效的证据。只补本次受影响行为的缺口；证据充分即停止，不按数量、覆盖率或场景类别扩面。
- 开发批次使用受影响验证。完整 release 门禁在适用的正式 release 边界执行。命令从当前项目和已接受计划选择，不把整套脚本列表变成每次开发的前置。

当前 UX 首个生产增量使用已接受计划中的真实 RCC 执行链和 Ego14 页面验收。业务样本只需证明本次输入、执行、语义投影和交付；不固定为某种外部工具任务。

## 输入与任务分流

**简单回答：**真实浏览器输入，经显式 Brain 整理与分流，直接形成并展示回答。它不创建 Draft、FIFO 任务、产品 Task 或任务 checkpoint。

简单回答的成功须有本次真实 Provider 执行返回的原 typed ProviderSettlement receipt，关联同一 interactionId 和 inputRevision，通过既有 validateProviderSettlement()，且 state 为 succeeded。非空回答、trace 或显式 Brain 状态不能替代该凭证。凭证缺失、无效、不匹配或未成功时，attempt 为 INCOMPLETE，记录具体缺证据与恢复责任。

**复杂任务：**新建任务表单的提交本身即确认。显式 Brain 在同一次提交中整理标准任务输入，按既有 FIFO 交付隐式 Brain，再由真实运行时执行和交付。不得增加第二次新任务确认。已有任务的目标、范围或处理方式变更仍须单独确认。

执行轮次和角色调用由真实动态编排决定。一次任务能完成时，不强制制造多个 turn；需要长程迭代时，核对实际 checkpoint、交付与后续 Planner 关系，不用固定角色顺序替代动态编排。

## 受影响行为的真实验收

- **输入与结果：**从实际产品表单提交，核对同一输入、interaction、Task 和最终交付的权威关联。正文须在公开读取入口与页面实际可读；列表、状态或 descriptor 存在不能替代正文。
- **执行观测：**核对本次受影响的阶段、当前动作、等待对象和已有等待信息。Provider 请求、工具调用、工具结果与最终输出保持各自真实语义和关联，不能相互冒充。
- **失败与恢复：**只检查本次影响的失败、等待、取消或恢复路径。页面给出真实原因和下一步，技术详情保留原始错误与关联证据；不静默失败、伪造成功或无限转圈。
- **阅读与导航：**使用同一真实 Task 的公开投影验收本次受影响视图。current、semantic、actions、raw、计划历史、实例、checkpoint 和 Context 各保留自己的身份；浏览、刷新、历史选择和展示偏好不能推进任务或改写控制状态。
- **checkpoint：**当前执行位置由权威控制事实解析，用户 viewed 位置独立。核对适用的精确选择、筛选、分页、错误保请求身份、返回当前和晚响应行为；不得用最新历史项替代未知 current。
- **分层与双端：**受影响主层显示人类可读语义，技术字段按需进入详情。适用的桌面侧栏与手机底部抽屉使用同一语义与控件；验证本次改变的入口、返回和操作，不重复检查无变化页面。

只读展示变更可复用有效的真实 Task 与 receipt，不为验收额外创建任务。输入、执行或控制行为变更须保留本次真实操作和结果。读取不得为取得展示数据再次触发 Provider 执行。

受控 HTTP、录制 replay 或 fixture 可以用于作者复现和抓错，但须明确证据边界。它们不证明生产路由已挂载、真实 Task 已完成或真实 RCC 已运行。API/Runtime 证明也不能替代受影响的浏览器交互。

## 候选与回执

每份验收记录只绑定它实际证明的候选和入口，至少保留适用的：

- 候选 SHA/tree、运行构建身份、访问 URL、mode、control root 与 owner。
- 输入或阅读目标、interaction/Task/operation 等权威关联，实际执行与交付 receipt。
- 对应断言、原始结果或日志，以及证明界面行为所需的截图。
- 未验证部分、首次偏离、原始错误、恢复责任和资源状态。

候选存在影响验收的未提交输入时，记录 HEAD/tree、相关 tracked diff 的 SHA-256，以及相关 untracked 文件路径与 SHA-256。正式集成使用已提交候选。输入变化只使受影响证据失效，不因记录笔记、派单或汇报重跑未变用例。

真实产品 receipt 和截图写入产品配置路径解析器从 `~/.humanagent` 派生的 `runNotesRoot/<attemptId>/`，截图位于 `shots/`。记录实际路径和 attempt 关联；候选 `dist/` 只作临时构建或浏览器产物，不能冒充持久 receipt root。受控代码复现保留在其独占 run 目录，并明确它不是产品 Task receipt。

复用当前项目中适用的 runner 或真实浏览器入口，不为记录证据新造一套执行框架。脚本存在、退出 0 或外部 checker 通过，都只证明其实际断言范围。观察或 checker 失败可将 attempt 记为 INCOMPLETE，不得据此改写已经提交的业务终态。

失败尝试保留首次偏离和必要证据，不能充当成功记录。缺少适用真实入口、交付或收口证据时，明确标 INCOMPLETE 或 UNVERIFIED。

## 资源收口

开始前登记本次新建或明确归本次所有的 Task、临时 workspace、专用 control root、服务 PID/端口、浏览器资源及日志位置。不得把真实项目 workspace、共享服务、用户浏览器或其他任务的资源列入删除范围。

无论成功、失败、超时或取消，都执行适用的收口：

1. 对本轮创建且需要结束的测试 Task，沿正式 task-scoped stop 通道收拢。取消 Provider 请求不等于停止完成。用权威状态核对实际终态、checkpoint 和副作用责任；未 settled 时记录 INCOMPLETE，保留恢复必需资源与唯一 recovery owner。仅阅读既有 Task，不因验收结束而停止它。
2. 保存必要 receipt 和截图。目标仍在执行时复用既有浏览器 TaskSpace/Page；只关闭本轮独占且不再需要的上下文，不为每次尝试重建浏览器，不关闭共享 daemon 或用户页面。整个目标结束时按浏览器资源 owner 收口。
3. 任务 settled 且服务不再承担恢复责任后，只通过正式服务入口或本轮记录的精确 PID 停止本轮临时服务。不得批量杀进程、按端口扫描后终止或停止他人服务。
4. 只删除本轮创建、证据已保存且不再需要的专属临时数据。未 settled 的 Task 保留恢复所需服务、路径和责任。产品 receipt 与必要截图保留为交付证据。代码 worktree 按项目 SESE 生命周期由其 owner 单独收口。
5. 对已执行的收口核对实际结果：自有临时 PID 已退出、端口关闭、删除路径不存在。仍需保留的资源列出用途、owner 和关闭条件；失败记录原错和下一步，不能只写 cleanup: done。

A0 没有产品 Task，不伪造 task stop 或 checkpoint settle；仍须核验本次 Provider 收拢与适用资源状态。未确认停止完成时不得删除恢复数据或宣称清理成功。

## 正式交付

完整且重大的 milestone 完成作者排障、受影响测试和适用真实入口验收后，在正式提交或集成边界做一次覆盖完整候选与架构的独立 Review。内部节点、小修、文档对齐和常规源码候选不单独触发 Review。

满足门禁后按项目标准交付：合入 main，执行适用的 release 构建、检查和本地安装，使用项目正式 restart 通道更新实例，验证运行产物与已验候选一致，再 push origin/main。不能以源码版本、版本号或 connected 状态替代正式运行证据。

安装与运行记录保留适用的 release artifact 路径和 SHA-256、安装入口、实际 binary 路径与身份、服务 PID/构建身份、真实页面结果及资源收口。候选验证与安装后验证各证明自己的范围，未变证据直接复用。

**放行条件：**本次需求与关键不变量的证据足够，适用的真实 Provider／公开入口／浏览器行为和交付已证明，必要测试与独立 milestone Review 通过，适用安装运行结果与候选一致，本轮测试资源收口核对通过。正式运行所需的保留资源有明确 owner 和用途。未 settled 的测试任务、收口失败或完整目标必需项仍缺证据时，保持 INCOMPLETE，不将恢复保留写成清理成功。
