# 面向人的语义分层展示设计

创建：2026-10-11；更新：2026-10-12（America/Los_Angeles）。  
需求绑定：项目需求库 `requirements_version: 13`。  
状态：DESIGN；本次重画 UX 和展示示意，不修改运行代码、不声明真实产品验收通过。

## 1. 展示目的与必要性

每层先确定用户要回答的问题，再决定显示内容。字段存在、模块正在运行、接口能返回，不构成展示理由。只有帮助理解当前情况、做决定、取得结果或核对依据的信息进入当前层。

默认展示中文语义，不显示状态枚举、调用名、模型协议、内部 ID、摘要哈希、原始 JSON、轮次字段和资源账本。真实任务结果本身若是代码/结构化文件，可以按用户要求打开；不能把其技术格式当成产品状态文案。

必要的失败、未知、影响与用户决定直接可见。隐藏的是无关字段和技术展开，不隐藏失败或未完成责任。语义没有来源就不猜测：明确说哪些结果尚未确认，不能用空列表、绿色成功或无意义动画遮掩。

## 2. 人的阅读层级

层级是可选择的阅读深度，不要求逐层走完。低层不把其全部信息堆到高层；高频结果/操作可以直接打开。

| 层 | 用途 | 必须显示 | 出现条件 | 默认不显示 |
|---|---|---|---|---|
| 对话入口 | 说出需求并得到回答 | 用户输入、直接答案；确有信息缺口时问具体问题 | 始终有输入入口；简单问答直接结束 | 空任务卡、任务模板表单、规划/执行角色、进度账本 |
| 任务总览 | 知道有哪些事要关注 | 人类可读任务目标、业务状态；需要用户行动时的提示；结果入口 | 存在复杂任务或用户主动进入任务列表 | 内部 ID、子调用树、模型请求、正常同步日志、全量计划 |
| 任务详情 | 理解这一件事并采取必要行动 | 目标、正在做什么、已得到什么；若有未完成/阻塞显示影响与下一步；真实合法操作 | 用户打开某个任务；需要决策时可直接到相关区域 | 每个子 agent 的完整过程、无结果的空面板、技术错误栈 |
| 处理经过 | 理解结果怎么得出、方案为什么改变 | 有来源的业务步骤/结果、方案变更原因、已保存的阶段回顾；当前进展与正在看的旧记录分开 | 用户主动展开，或需要理解某次失败/调整 | 固定四角色流程、每个模型请求、重复工具 ACK、预算字段 |
| 资料与证据 | 查阅成果并核对依据 | 文件/资料名称、内容摘要、它支持哪个结论、可打开的实际内容 | 已有资料/结果，用户打开；关键决定所需依据可直接访问 | 默认原始协议/Journal 行、哈希串、无关参数 |
| 技术记录 | 定位具体实现问题 | 按需查看原始记录、关联标识与错误细节，并注明其用途 | 用户明确要求技术诊断/原始记录 | 默认入口中的所有技术字段；不自动展开 |

没有有效内容的区域不渲染，不放空表格、空角色卡或一排禁用按钮。不存在任务时显示输入入口，不制造空任务树。项目/执行者等导航只在存在多个真实范围或用户主动选择时出现；同一范围不重复多层摘要。

## 3. 按语义显示，不按内部事件翻译词

复用 context-events 的共同语义与 typed UI projection。展示规则只决定分组/措辞，不是第二个任务完成判定器。以下是设计示例，不是硬编码前端状态映射表：

| 事实语义 | 面向人的表达 | 必要显示/隐藏 |
|---|---|---|
| 任务已接收但尚未开始 | “任务已收到，还未开始处理” | 仅已提供时解释等待原因；不露出 created/FIFO |
| 已观察到实际核对资料 | “正在核对资料” | 显示实际工作，不显示工具方法名或模型名 |
| 已有资料结果，后续尚未确认 | “资料已找到，后续处理结果尚未确认” | 不把一个工具成功升级成任务完成 |
| 需要用户选择范围 | “还需要你确认整理范围” | 显示选择如何影响任务及必要选项；不显示内部 Attention 编码 |
| 错误后暂不能继续 | “处理已暂停，恢复后将从未完成处继续” | 显示已知影响与真实可用下一步；不默认判整任务失败 |
| 副作用/收拢尚未确定 | “是否已停止尚未确认” | 保留未知与责任，不包装成“已停止” |
| 已提交任务成果与终态 | “已完成”并给出成果和必要结果说明 | 不再显示“正在处理”、生成动画或无关过程 |
| 内容读取过期/失败 | “新进展暂时无法读取，以下是上次确认的内容” | 保留旧内容并明确新鲜度问题；正常同步不刷技术日志 |

## 4. 每个区域的保留判断

显示当且仅当至少服务一个当前问题：现在发生什么；我已得到什么；是否需要我决定；我能做什么；这个结论有什么依据。重复同一事实、无来源推测、只服务内部调度或没有当前数据的内容不显示。

例：任务在处理中时显示真实活动与已有阶段结果；没有交付就不放空“成果”栏。需用户决定时把该决定提升到任务卡/详情顶部。已完成时先显示成果；处理历史可按需打开。未知时显示未知的具体对象和下一步，不显示一堆未确认技术标识。

## 5. 与最新双大脑设计的连接

简单问答只走对话入口。复杂需求由显式大脑整理并派单；用户默认看到目标和“已收到/正在处理/需要你确认/结果”等语义，不必理解派单模板、临时续推、checkpoint 或模型 finish reason。

任务内部动态编排可多次探索、计划、执行、审查；处理经过只展示真实工作，不把这四类能力变成固定四段进度条。阶段 checkpoint 对用户称“阶段回顾/已保存进展”，只在复盘/恢复有用时展示；四项语义用人类可读标题呈现。

临时续推提示词与内部恢复指令不进入对话、历史过程或用户成果。停止/恢复等操作仍调用原控制 owner；只读过程与证据页不执行控制。

## 6. 唯一数据边

Core/Runtime/Journal 提供真相与恢复责任；context-events 归类/配对/生成共同叙事；UI projection 按当前用途组织语义与必要区域；App 提供 typed 查询/更新；浏览器呈现共享控件并按需展开。

浏览器不解析 raw 推导业务阶段，不从标题造身份，不从前端计时器推导失败，不生成伪进度百分比。资料证据通过既有只读查询获得；技术记录不回流成业务状态。

## 8. 桌面与手机排版

- 本节适用于所有产品表面中的下一层内容，包括详情、证据、处理经过与配置；不是只约束设置弹层。
- 桌面保留主内容，下一层在旁侧面板展开，避免不必要整页跳转；深层内容在同一面板递进并可返回。
- 手机以下方弹出的抽屉进入下一层；同一个抽屉替换内容，保持任务/来源、层级标题和返回入口，不连续堆叠弹层。关闭回到原内容，返回上一层保留位置。
- 结果和必要决定在窄屏仍优先可见，文字换行而非隐藏；抽屉内正文滚动，标题/返回/关闭保持可达；底部留设备安全区。
- 语义和层级在两设备一致，不为手机复制另一套状态解释。

## 9. 主动配置位于四个角落

四角各有一个持续可见、可直接操作的配置按钮；按钮是主动配置入口，不收进汉堡菜单或页面顶部设置栏。每个表面保持相同的位置与职责：左上工作范围、右上查看方式、左下显示设置、右下输入设置。具体选项随当前页面和真实能力变化；没有可用的替代选项时只显示当前值与原因，不生成空表格、假选项或无效按钮。

点击任一角落按钮，在手机底部抽屉/桌面旁侧面板打开对应设置。右上按钮承载查看方式选择（`current/semantic/actions/raw`），不再同时保留一组重复的行内模式按钮；用户主动选择 `raw` 即表示主动打开技术记录。工作范围只使用当前真实可读的 conversation/task/project 身份，不从标题、目录或角色推断。

主动配置与当前任务中的必要操作分开：查看结果、回答决定、返回上一层、关闭展开内容不是全局配置按钮。偏好只改变显示、查看或输入方式；任务目标和执行状态仍由原任务 owner 管理。

配置按钮在简单问答和复杂任务中都保留相同的四角位置。简单问答的工作范围显示当前对话，不制造 Task/Project 层级；各配置面板只展示当前产品和能力实际支持的选项。
