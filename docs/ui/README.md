# HumanAgent Runtime Operator Console

状态：`RUNTIME-CONNECTED`
工作总览：[dashboard.html](dashboard.html)  
任务输入首页：[index.html](index.html)
任务列表第一入口：[tasks.html](tasks.html)  
任务详情与输入决策：[task.html](task.html)  
运行任务看板：[task-dashboard.html](task-dashboard.html)  
后台观测：[observation.html](observation.html)  
历史视觉原型（非产品入口）：
[interaction.html](interaction.html)

当前产品入口从 `index.html` 接受用户任务，经显式大脑生成可确认草稿，确认后进入
隐式队列。运行状态入口包括 `dashboard.html`、`tasks.html`、`task.html`、`task-dashboard.html` 和
`observation.html`。这些页面通过 `runtime-api.js` 消费 HumanAgent Runtime API，不读取
Journal、DSH Session、RCC raw frame 或 debug log。`index.html` 不呈现静态运行状态，
队列确认和任务状态都来自 Runtime projection。

## UI brief

- Surface：Operator Console。
- Mode：`operate + read`。
- Audience：需要观察、判断和控制长程任务的使用者/operator。
- Primary task：快速回答“现在发生什么、是否需要我决定、我能做什么”。
- Product truth：页面只呈现 Runtime typed projection；按钮只调用正式 Runtime
  operation。`fake` 模式必须显示 `mode=fake`，不得伪装成真实 Provider 结果。

## 四个正常界面责任

### Task List：任务列表第一入口

任务列表是 Task 产品的第一入口，不把每个任务渲染成详情卡片。默认按三组高密度呈现：

- 当前运行：任务、状态、负责 agent、当前节点、正在处理、第几轮、进度、最近更新时间和详情入口。
- 需要你决策：需要你确认处理方式、调整范围或补充信息的任务，置于独立优先组。
- 历史任务：最后状态、最后处理结果、结果和历史入口。

桌面使用语义列表表格快速扫描；手机版把运行任务压缩成任务、状态、负责 agent、当前工作、进度和更新时间，把决策任务压缩成情况、建议和处理入口。搜索、状态筛选和组切换只改变列表投影，不把后台节点或完整决策流带入首页。当前运行任务点击后进入 `task-dashboard.html`；需要你决策的任务进入 Task Detail。

列表字段直接来自 Runtime task projection；投影尚未给出当前节点、轮次或归属 agent 时，单元格显示明确的"尚未投影"占位，不用其它字段顶替，也不写死示例任务。

### Dashboard：简洁状态入口

Dashboard 只负责回答四个问题：有没有待处理事项、现在有哪些任务正在处理、最近收到了什么输入、历史任务有哪些。它不展示内部职责、节点链条、队列、器官状态或处理阶段；每个任务行都是进入该任务处理和详情的入口。

### Task Detail：任务处理和任务观测入口

人的正常任务输入输出界面，也是当前任务的后台观测入口。它展示收到的输入、调查结果、建议方案、任务状态、输出和 artifact；需要选择时提供固定选项和自定义输入，不需要批准的步骤直接继续。任务内部的详细观测从“任务观测”入口进入；不把内部职责或实现阶段作为主页面文案。

任务处理的内部流转属于实现，不作为主页面文案；完整记录从任务详情的“任务观测”入口进入。

页面先展示输入内容、项目状态调查结果和建议方案。若方案需要用户选择，提供若干选项和“自定义”；若不需要批准，则直接继续。只查询状态不会改变任务。

任务详情主面按用户能理解的内容分为四段：

1. 当前状态：任务现在处于什么状态。
2. 输入和调查结果：收到的内容、项目状态调查和已有事实。
3. 建议方案：根据调查结果提出的处理建议。
4. 需要你决定：只有需要选择或调整时才出现选项。

完整横向路径、历史节点、输入/输出引用、evidence 和负责者通过节点卡片的抽屉入口查看。抽屉打开后焦点落在当前路径节点；关闭后焦点回到原卡片入口。

### Task Dashboard：运行任务看板

运行列表点击后进入 `task-dashboard.html`，这是单个运行任务的看板，不是用户决策页。它只回答“这个任务里谁在工作、正在处理什么、最近输出了什么”:

- 任务摘要：用户输入、任务目标和当前任务状态。
- agent 工作卡片：每个 agent 的输入、当前输出、状态和更新时间预览。
- 动态过程：点击卡片后打开详情，展示过程摘要和当前输出；不暴露私有思维链。
- 任务反馈：是否需要用户处理；需要选择时再回到 Task Detail 的交互入口。

看板中的交互 agent、任务编排 agent、记忆 agent 和具体执行 agent 是产品功能角色，不用器官类比作为页面标题。更深的节点树、证据和递归观察仍从“深入观测”进入。

### 运行控制

运行控制界面。处理任务状态、Attention、checkpoint、继续、停止并收拢和运行控制；后台诊断只作为特殊入口。

### 后台观测

后台的只读观测界面。以四条垂直结构展示输入、任务安排、运行关联、条件检查和执行记录：

- agent 链路：顶部显式呈现"上游 agent → 下游 agent"的角色顺序（交互 → 任务编排 → 执行 → 审核 → 经验整理），有节点归属的角色高亮。
- 归属框：节点按投影里的 `agentId`（回退 `ownerAgentRole`）精确匹配归属角色分组进框，五个角色框都渲染；投影未给出归属时进入"归属未投影"框，不按 `owner` 模块名或关键词猜归属；无节点的框显示"当前 scope 没有归属该 agent 的节点"，不借其它 agent 的节点填充。
- 竖向 DAG：节点自上而下排列，桌面与手机都是单列，不横向铺开。
- 节点顺序与行号来自流水线注册表（`PIPELINE_ROWS`）；注册表接线前，`observation.js` 里的 `PIPELINE_ROWS` 是唯一一份顺序表，不得再出现第二份。
- 边：已完成的流程用静态线、箭头在线的中点；正在运行的流程用流动线、箭头在终点；未开始的流程是静态虚线且无箭头。同一归属框内相邻的节点用竖直直线连接；跨归属框或同框非相邻的节点一律走节点框右侧的竖直通道绕行，任何边都不穿过节点框。

节点是按钮；点击从底部打开 drawer。有子节点时可以递归进入，使用面包屑和返回栈返回上层。它不提供消费、重试、修改或控制动作。

## 呈现边界

### 正常任务界面

正常页面直接呈现：

- 当前任务和目标。
- 当前运行状态、影响范围和最后更新时间。
- 需要人决定的事项。
- 继续、停止、确认、查看证据等人类动作。
- 简化后的可读活动时间线。

### 后台细节

默认不打扰人：

- 内部处理阶段。
- 重试、降级和恢复细节。
- 原始事件、控制字段、epoch、队列和诊断信息。
- 低级 provider、transport、session 和工具内部状态。

这些内容只能通过“后台详情 / 诊断”这一类特殊入口打开，不参与正常任务操作路径。

## 交互定义

`tasks.html` 是任务列表第一入口；`dashboard.html` 是简洁状态入口。它们用低保真 HTML 定义：

`tasks.html` 定义：

- 当前运行、需要你决策、历史任务三组任务索引。
- Desktop 高密度扫描行（任务、状态、负责 agent、当前节点、正在处理、第几轮、进度、最近更新）和 Mobile 紧凑任务行（任务、状态、负责 agent、当前工作、进度、更新时间）。
- 搜索、状态筛选、组切换、空结果和任务详情导航。
- 当前运行区是 agent 运行看板索引：任务、状态、负责 agent、正在处理、当前进度、最近更新和详情入口。
- 需要你决策区是显式交互入口：情况、建议和"进入处理"，不复用运行看板字段。
- 列表不展开后台动态过程；点击当前运行任务进入 `task-dashboard.html`。

`dashboard.html` 定义：

- Desktop 双列状态入口和 Mobile 单栏状态入口。
- 待处理事项、正在处理的任务、最近输入（来自你/来自任务）和历史任务。
- 每个任务行进入对应 Task Detail；不显示内部职责、器官类比和决策链条。

`interaction.html` 是历史视觉原型，不作为当前 Runtime 入口。它用低保真 HTML 记录：

- Desktop 三个主要区域：任务导航、当前任务、需要处理。
- Mobile 单栏顺序：当前任务、需要处理、后台特殊入口；底部导航切换任务/待处理/历史的阅读焦点，诊断仍是特殊入口。
- 显式动作：继续、停止并收拢、允许继续写入、查看 checkpoint。
- 隐式入口：`details` 后台详情、只读诊断 dialog、原始事件入口。
- 交互状态：running → stopping（停止完成由后端投影为 stopped，不由页面假造）；attention open → acknowledged；任务切换；诊断展开。
- 任务切换会同步当前任务摘要、待处理事项、最近变化和可用动作；无效动作不呈现。

`task.html` 定义 Task Detail：

- 任务标题、生命周期状态和“当前任务 + 当前状态”焦点。
- 当前状态、输入和调查结果、建议方案、需要你决定四个内容区。
- 需要选择时提供固定选项和自定义输入；不需要批准时直接继续。
- “任务观测”进入该任务对应的后台节点、历史和 evidence；不把内部实现阶段写进主视图。
- 不暴露或伪造私有 chain-of-thought。

`task-dashboard.html` 定义单个运行任务的执行看板：

- 展示用户输入、任务目标和当前状态。
- 展示交互 agent、任务编排 agent、记忆 agent 以及具体执行 agent 的输入/输出预览。
- 点击 agent 卡片打开动态过程摘要和当前输出；静态原型不连接 runtime。
- 不把运行看板改造成用户决策表单；需要用户选择时通过任务反馈回到 Task Detail。

`observation.html` 定义 Pipeline Observation：

- 顶部 agent 链路和五个归属 agent 分组框。
- 当前 scope 的竖向节点序列和状态。
- 节点详情 drawer：底部 sheet，打开后 DAG 仍然可见；左栏是工具调用历史（工具调用、工具返回），右栏是 summary，交接内容在独立一页；关闭后焦点回到触发节点卡片。
- 子 scope 递归进入、面包屑和返回。
- 只读 evidence/input/output 引用，不提供后台消费和控制动作。
- 左栏与 summary 只呈现工具调用、工具返回和 agent 自己写入的结论，不呈现模型私有思维链。
- 键盘焦点在 drawer 内循环，关闭后返回触发元素；主要触控目标至少 44px；`prefers-reduced-motion` 下流动线退化为静态状态区分。

## 视觉与交互决策

- 视觉方向：安静、黑白灰、高密度；不使用装饰性渐变、强阴影或重复卡片。
- 消融原则：每个页面只保留会影响判断或下一步操作的信息；重复统计、实现术语和解释性说明移出主层。
- 信息层级：当前状态 → 已有事实 → 建议/下一步 → 需要你决定；历史、路径和 evidence 从抽屉或特殊入口呼出。
- Desktop：任务列表使用高密度表格；任务详情用主内容区承载状态和决策；Dashboard 只做状态入口。
- Mobile：单栏排列，任务标题、状态和主动作优先；次要信息折叠到行内或详情抽屉。
- 触控：主要动作至少 44px hit area。
- 状态：支持 ready、running、waiting、attention、stopped、stale、disconnected 的静态演示。
- 动效：只使用短暂的 `transform`/`opacity` 反馈；`prefers-reduced-motion` 时退化为状态切换。
- 参考合并：采用 `emilkowalski/skills` 的设计工程原则（响应快、动画有明确目的、避免 `transition: all`、按压反馈）与本项目的结构/无障碍/状态约束；不直接复制其示例组件。
- 颜色：页面只使用黑、白、灰和语义状态差异；组件不引入第二套视觉语言。
