# 基于显式大脑派单模板的临时续推提示词

需求绑定：`.appsdk/requirements.json`，`requirements_version: 13`。  
状态：DESIGN；没有修改运行代码或声称 Provider 已接线。

## 1. 适用入口

显式大脑先分流：简单问答直接回答并结束，不创建任务、不走长程续推。复杂问题整理成标准任务模板并派发；续推只在这条任务执行路径使用。

既然显式大脑已分流，不再要求模型输出 `is_simple_qa` / `task_complete` control block。是否需要继续由该路径已有任务/assignment 真相判断，不从模型标签或 finish reason 重建。

## 2. 本次推理使用的实际输入

- 基础 context 由唯一 Context owner 装配：历史语义 checkpoints＋当前 turn 的真实活动。
- 同时装配显式大脑**已确认派单模板的实际内容/引用**，沿用该任务的目标、范围、约束、交付与完成要求，保持对应 revision/身份。不另造一套续推目标字段。
- 恢复时从任务真相重建同一模板和未完成位置。模板缺失属于装配缺口，由 Runtime 恢复或报告缺口，不能要求模型凭空补出目标。
- 临时续推指令引用这份业务模板；不重复把整份任务 payload 填进提示词或每次生成新任务。

## 3. 通用临时提示词

```text
继续当前任务。先重新做 orientation：读取显式大脑派单的任务模板，明确当前要完成什么，以及适用的范围、约束、交付和完成要求。

结合已有工作与当前结果，对照派单要求找出尚未完成的部分，按当前职责选择必要的下一步行动并继续完成。
不要重复已经确认完成的工作；保留未知、未解决问题和在途责任，不把一次模型请求结束当作任务完成。

需要结束当前 turn 时，按既定任务协议完成压缩、总结和交付。总结说明目标、做了什么、结果和预计下一步。
如果这是错误后的恢复，承接原 turn 的未完成位置继续处理。
```

这段提示不要求 context 中存在 `current_goal`、`accepted_semantic_state`、`missing_closure_actions` 等固定字段，不要求模型补填一套复杂 goal 表单。简单问答不调用它；复杂任务依据显式大脑真正提供的派单模板。

## 4. 临时指令隔离

指令只送入本次推理请求，不追加到规范 history、checkpoint 或下一请求/下一 turn 的 context。下一次仍需续推时，根据当时任务状态重新使用这段指令。

任务模板是原业务依据，可以按既有 Context owner 的规则装配和保留；临时“继续、重新 orientation”指令不是任务内容，不能把二者一起删除或一起持久化。

Provider/Prompt Renderer 只编码本次有效输入；下一请求从规范 context 重建，不拿包含旧临时指令的整段 wire 请求作为 history。已有 wire 证据即使有副本，也只是证据，不回填活动上下文。

## 5. 完成与错误

复杂任务没有完成时继续动态推理，角色调用不固定顺序。阶段 turn 正常收口按既有 checkpoint/Planner 迭代规则；任务完成或明确失败才结束任务运行。

错误可多次 retry 后暂停，恢复原 turn；暂停、未知和资源不足不冒充任务完成。具体 stop/settlement 与副作用事实仍归 Core/Runtime/Journal，不由该提示词或 model finish reason 决定。
